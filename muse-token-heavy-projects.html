#1 PRIORITY

1. Repo-wide migration runner

Migrate a real 50-200 file repo: Jest->Vitest, ESLint->Biome, unittest->pytest, or React class->hooks.

  • Why token-heavy: map all files, edit each, fix fallout.
  • Muse edge: CLI loop read -> edit -> test -> fix vs Cursor/Codex UI dependence.
  • Run: same repo + one-line prompt. Score: tokens, tool calls, time to green, human interventions.
  • Weekend slice: pick one 50-file repo, run migration, require green tests.
#3 PRIORITY

3. Test-and-fix swarm

Take a repo with weak tests. Generate integration tests to >80% coverage, then fix all failures found.

  • Why token-heavy: large generated output, then read own failures.
  • Muse edge: sustained autonomy vs Claude chat / Grok one-shot.
  • Run: measure coverage delta, faults found, false positives.
  • Weekend slice: one module, 20+ tests, full green run.

Full reference list

  • 2. Cold-start feature in unfamiliar monorepo - add cross-cutting feature from one prompt.
  • 4. Polyglot CLI toolchain - Python CLI generating TS + Go + Rust projects with e2e checks.
  • 5. Docs-to-code reproduction - generate server + client + mocks from 10k-line OpenAPI spec.
  • 6. Bug-hunt marathon - 10 injected bugs, repro-bisect-fix with proof logs.
  • 7. Self-healing CI setup - lint + typecheck + test + Docker + Actions until green.

Fair comparison checklist

  • Same starting repo + same prompt, no hints
  • Log: tokens, tool calls, time, interventions, correct diff size
  • Muse wins on 20+ step shell/test loops; skip single-file snippet demos
